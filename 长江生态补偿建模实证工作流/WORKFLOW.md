# 长江横向生态补偿：建模与实证专用工作流

## 1. 工作边界

本工作流只负责：

1. 经济机制形式化；
2. 变量、样本与数据结构审计；
3. 计量模型建立与识别；
4. 代码、估计、诊断和稳健性检验；
5. 将实证结果整理为可供正文写作者使用的技术结论。

正文叙述、政策分析与语言风格由论文文字负责人主导。本工作流不得为了迎合既有文字结论而选择模型、样本或显著性结果。

## 2. 当前研究对象

研究对象为长江上下游省级政府横向生态补偿。下游省份记为 \(i\)，上游省份记为 \(j\)，年份记为 \(t\)。

核心对象包括：

- 上游保护机会成本：\(C_{jt}\)；
- 下游生态受益或最高支付意愿：\(B_{it}\)；
- 实际双边补偿支付：\(P_{ijt}\)；
- 可供谈判分配的合作剩余：

\[
S_{ijt}=B_{it}-C_{jt}.
\]

只有当

\[
S_{ijt}>0
\]

时，纯粹依靠双方收益—成本的自愿补偿交易才存在可分配的正剩余。若 \(S_{ijt}\leq 0\)，应单独讨论中央财政兜底、生态公共品供给或非市场政策约束，不能沿用同一套自愿议价解释。

## 3. 总体路线

工作流分为八道门：

1. 配对支付真实性门；
2. 成本与收益可识别门；
3. 理论议价映射门；
4. 数据结构和样本独立性门；
5. 基准估计门；
6. 模型诊断门；
7. 稳健性和替代解释门；
8. 结果交付门。

任何一道门未通过，不进入下一阶段，也不得将占位数值写成论文结论。

## 阶段 A：数据账本与配对真实性审计

### A1. 必须回答的问题

1. 每笔补偿款能否观察到明确的付款省 \(i\)、收款省 \(j\)、年份 \(t\) 和金额 \(P_{ijt}\)？
2. 同一笔省级总支出是否被重复分配给多个上游省？
3. 论文中的 28 组配对来自真实协议，还是由研究者根据上下游关系构造？
4. 3 个下游省与 7 个上游省的完全组合只有

\[
3\times 7=21
\]

组。新增的 7 个“次级配对”是否重复已有省对、重复使用同一资金流或仅改变名称？
5. 2018—2025 年是否每年都存在可比的双边协议？政策尚未执行年份能否定义为零，而不是缺失？

### A2. 通过条件

必须形成逐笔数据账本，每一行至少包含：

\[
(i,j,t,P_{ijt},\text{协议名称},\text{资金来源},\text{公开出处},\text{是否估算}).
\]

若真实的 \(P_{ijt}\) 不可观察，则禁止直接估计双边议价模型。改走以下路线之一：

- 省级总支付模型；
- 网络流量分配模型；
- 带测量方程的潜变量模型；
- 明确标注为情景模拟而非实证识别。

### A3. 输出

- `data/payment-ledger.xlsx`
- `data/pair-definition.xlsx`
- `notes/pair-audit.md`

## 阶段 B：成本与收益核算

### B1. 上游机会成本

需要区分：

- 观测到的生态保护投入；
- 因生态约束损失的经济产出；
- 反事实机会成本；
- 中央纵向转移支付已经覆盖的部分。

建议定义净机会成本：

\[
C_{jt}
=
\widehat{Y}_{jt}(0)-Y_{jt}(1)
+E_{jt}
-V_{jt},
\]

其中：

- \(\widehat{Y}_{jt}(0)\) 为无新增生态约束时的反事实产出；
- \(Y_{jt}(1)\) 为实际产出；
- \(E_{jt}\) 为直接生态治理支出；
- \(V_{jt}\) 为已获得的纵向补助及其他成本抵扣。

如果使用 DID 估计反事实损失，应先明确处理时点、处理组和对照组。基准式可写为：

\[
Y_{pt}
=
\alpha_p+\lambda_t
+\beta D_{pt}
+\gamma^{\top}X_{pt}
+\varepsilon_{pt}.
\]

必须检查：

- 平行趋势；
- 错位处理时点下的异质处理效应；
- 政策前预期效应；
- 生态红线变量是否实际具有省际和时间变化；
- 2018 年以前是否有足够的政策前时期。

不得用一个缺乏识别变化的生态红线比例直接推导因果机会成本。

### B2. 下游生态受益

GTFP、水安全、高耗水行业占比不是天然可加总的货币收益。必须区分：

1. 受益驱动因素；
2. 受益代理变量；
3. 货币化的支付意愿上限。

建议优先构建：

\[
B_{it}
=
B^{\mathrm{industry}}_{it}
+B^{\mathrm{water}}_{it}
+B^{\mathrm{risk}}_{it},
\]

并为每个分项提供独立核算口径。若无法货币化，则仅将代理指标用于异质性方程，不直接声称其为“生态损益金额”。

### B3. 输出

- `data/upstream-cost.xlsx`
- `data/downstream-benefit.xlsx`
- `notes/valuation-assumptions.md`
- `code/01_cost_estimation.*`
- `code/02_benefit_estimation.*`

## 阶段 C：理论议价模型

### C1. 推荐的结构基准

实际支付应位于上游保留价和下游支付上限之间：

\[
C_{jt}\leq P_{ijt}\leq B_{it}.
\]

令 \(\theta_{ijt}\in[0,1]\) 表示上游获得合作剩余的份额，则：

\[
P_{ijt}
=
C_{jt}
+\theta_{ijt}\left(B_{it}-C_{jt}\right).
\]

等价地，

\[
\theta_{ijt}
=
\frac{P_{ijt}-C_{jt}}
{B_{it}-C_{jt}}.
\]

这一定义直接对应议价分配，优先于用随机前沿的方差参数替代议价权。

令议价份额满足：

\[
\operatorname{logit}(\theta_{ijt})
=
Z_{ijt}^{\top}\gamma
+a_{ij}+\tau_t+\xi_{ijt},
\]

其中 \(Z_{ijt}\) 可以包含：

- 上下游财政实力差；
- 水资源依赖度；
- 中央财政介入；
- 协议期限；
- 水质达标压力；
- 替代水源能力；
- 政治或行政协调机制；
- 上下游外部选择。

### C2. 与鲁宾斯坦模型的映射

若上游先报价，上游获得剩余的理论份额可写为：

\[
\theta^{R}_{ijt}
=
\frac{1-\delta^{D}_{it}}
{1-\delta^{U}_{jt}\delta^{D}_{it}},
\]

其中：

- \(\delta^{U}_{jt}\) 为上游等待的折现因子；
- \(\delta^{D}_{it}\) 为下游等待的折现因子。

经验模型必须说明财政压力、供水依赖、环境考核或中央协调如何映射到折现因子或外部选择。若这些参数不能被数据识别，应将鲁宾斯坦模型作为机制解释，不得声称直接估计了鲁宾斯坦议价权。

### C3. 规范性议价失衡指标

先确定规范基准份额 \(\theta^{*}_{ijt}\)，再定义议价偏离：

\[
I_{ijt}
=
\theta_{ijt}-\theta^{*}_{ijt}.
\]

例如：

- 对称议价基准：\(\theta^{*}_{ijt}=0.5\)；
- 按成本风险承担确定的基准；
- 按政策规定的权责权重确定的基准。

必须明确“上游份额较低”与“不公平”不是同一个统计命题。不公平判断依赖规范基准。

### C4. 输出

- `notes/theoretical-model.md`
- `notes/parameter-identification.md`
- `figures/bargaining-mechanism.pdf`

## 阶段 D：双边随机前沿的保留、改造或淘汰

### D1. 可保留的形式

双边随机前沿可以作为补偿金额相对于条件均值的双向偏离分解：

\[
P_{ijt}
=
X_{ijt}^{\top}\beta
+v_{ijt}
+\eta_{ijt}
-\mu_{ijt},
\]

其中：

\[
v_{ijt}\sim N(0,\sigma_v^2),\qquad
\eta_{ijt}\sim N^{+}(0,\sigma_\eta^2),\qquad
\mu_{ijt}\sim N^{+}(0,\sigma_\mu^2).
\]

但只有在充分理论约束和外部验证下，才能将 \(\eta_{ijt}\) 与 \(\mu_{ijt}\) 分别解释为上游抬价和下游压价。

### D2. 禁止直接使用的解释

以下比率：

\[
\lambda_\eta
=
\frac{\sigma_\eta}
{\sigma_\eta+\sigma_\mu},
\qquad
\lambda_\mu
=
\frac{\sigma_\mu}
{\sigma_\eta+\sigma_\mu}
\]

首先是潜在单边项的尺度或离散程度占比。除非给出严格映射，它们不能自动等同于鲁宾斯坦模型的议价权，也不能自动推出“某方获得了多少合作剩余”。

### D3. 推荐的双模型策略

主模型：

\[
P_{ijt}
=
C_{jt}
+\theta_{ijt}(B_{it}-C_{jt}).
\]

辅助模型：

\[
P_{ijt}
=
X_{ijt}^{\top}\beta
+v_{ijt}+\eta_{ijt}-\mu_{ijt}.
\]

比较两类模型产生的省对排序、年度趋势和异常观测。只有二者一致且通过外部验证时，才把随机前沿结果作为议价机制的辅助证据。

### D4. 模型选择规则

- 有真实 \(P_{ijt}\)、\(C_{jt}\)、\(B_{it}\)：优先结构议价模型；
- 有真实 \(P_{ijt}\)，但成本收益仅有代理变量：双边随机前沿可作为探索模型；
- 只有省级总支付：使用聚合模型或网络分配模型；
- 支付、成本、收益均主要依靠人为校准：定位为情景模拟，不做强识别表述。

## 阶段 E：估计与诊断

### E1. 基准估计顺序

1. 数据描述与缺失审计；
2. 省对支付真实性检查；
3. 上游成本估计；
4. 下游收益估计；
5. 合作剩余正值检查；
6. 结构议价份额估计；
7. 双边随机前沿辅助估计；
8. 时变与异质性分析；
9. 国际标尺情景校准。

### E2. 必做诊断

- 省对固定效应和年份固定效应；
- 下游省与上游省的多维聚类或适合小簇情形的推断；
- 参数边界和似然面；
- 不同初始值下的收敛；
- 半正态、截断正态、指数分布替代；
- 异常年份和异常省份影响；
- 真实配对与随机配对比较；
- 2025 年估算数据剔除；
- 21 个唯一省对与 28 个声明配对分别估计；
- 对重复资金流的敏感性分析。

### E3. 小样本推断

本研究的有效独立单位很可能不是 224 个省对—年份观测，而是有限数量的支付省、受偿省或真实协议。必须报告聚类层级，并使用：

- 小样本修正；
- wild cluster bootstrap；
- 贝叶斯后验区间；
- 留一省份法；
- 参数自助法。

不能仅通过增加人为配对，把名义样本量当作独立信息量。

## 阶段 F：稳健性与证伪

至少包括：

1. 剔除 2025 年估算数据；
2. 只保留 21 个唯一省对；
3. 只保留有正式协议和真实资金流的省对；
4. 替换成本核算口径；
5. 替换受益核算口径；
6. 替换议价规范基准；
7. 双边随机前沿分布替换；
8. 随机配对应产生无结构结果；
9. 伪年份检验；
10. 留一省份检验；
11. 国际标尺权重区间分析；
12. 对所有估算值进行上下界敏感性分析。

国际校准结果必须以区间或情景形式呈现：

\[
P^{\mathrm{recommended}}_{it}
\in
\left[
P^{L}_{it},
P^{U}_{it}
\right],
\]

不得仅报告缺乏不确定性的单点金额。

## 6. 缺失数据补充与模型降级路线

阶段 A 不以“填满原定面板”为目标，而以识别真实观测层级为目标。对缺失数据按以下四条路线依次处理。

### 路线 A：真实双边账本

只有同时观察到付款省、收款省、履约年度和实际清算金额时，才记为真实
\(P_{ijt}\)。优先来源为：

1. 财政部门拨付通知、预算和决算；
2. 生态环境部门决算、绩效自评和专项资金报告；
3. 正式协议及年度清算函；
4. 审计报告、人大建议和政协提案答复；
5. 已发表论文对原始政府文件的可追溯引用。

累计金额、资金池规模和协议出资上限不得直接拆成双边年度支付。未公开年份记为缺失，不记为零。只有路线 A 形成足够的真实省对—年份观测后，才恢复结构议价主模型和随机前沿辅助模型。

### 路线 B：省级总支付模型

若只能观察付款省年度总出资或收款省年度净收入，则分析单位改为
\((province,t)\)，不把同一笔总额复制分配给多个上游省。

可使用的结果变量包括：

- 省级横向补偿总支付；
- 省级横向补偿总收入；
- 省级净补偿头寸；
- 中央流域清算奖励；
- 是否为净付款方。

省级经济、财政、水资源和环境控制变量从国家统计局国家数据、水资源公报、生态环境统计年报及省级统计年鉴补充。

### 路线 C：协议或项目级资金流模型

若资金对应联合协议、考核断面、资金池或流域治理项目，则分析单位改为
\((agreement/river,t)\)。至少记录：

\[
(\text{协议或河流},t,\text{参与省份},\text{资金池},\text{实际清算},
\text{水质条件},\text{协议轮次},\text{中央奖励}).
\]

参与省份用于建立二部网络或超边网络，但同一资金流不得展开成多条虚构双边支付。赤水河、酉水、渌水、川渝长江干流和苏皖长江干流分别作为独立协议单元。

### 路线 D：情景模拟

当金额依靠协议比例、生态贡献权重或财政能力权重分摊时，必须标记为
`scenario_prediction` 或 `calibrated_amount`，并与真实支付分表保存。

模拟值只用于：

- 政策情景比较；
- 上下限区间；
- 权重敏感性分析；
- 规范性分配方案。

模拟值不得用于补齐真实 \(P_{ijt}\) 后再估计其决定机制。协议总额拆分、线性插值、机器学习预测和矩阵补全均不得伪装成实际支付。

### 路线选择顺序

1. 对每条缺失记录继续检索路线 A；
2. 无双边方向但有省级净额时进入路线 B；
3. 只有协议、河流或资金池数据时进入路线 C；
4. 必须依靠权重生成金额时进入路线 D；
5. 每条记录只进入一个主分析层级，防止同一资金流重复计数。

## 7. 数据采集工具路由

### 7.1 现有审计爬虫

用于政府静态网页、PDF、公开通知和来源哈希归档。所有金额先进入候选表，再经过人工规则核验后进入支付账本。

### 7.2 Crawl4AI

来源：`unclecode/crawl4ai`。

仅在普通 HTTP/PDF 抓取无法获得正文，且网页依赖 JavaScript、分页、懒加载或交互时使用。适用对象包括财政厅动态列表、决算附件页和需要浏览器渲染的政府检索页。

启用前必须：

- 固定版本；
- 在项目独立子目录中保存调用代码；
- 限制域名、并发和重试次数；
- 尊重 robots.txt、站点条款和访问频率；
- 保存最终 URL、抓取时间、正文哈希和失败原因；
- 不保存与结构复现无关的网页全文或 Markdown。

### 7.3 Firecrawl

来源：`firecrawl/firecrawl`。

仅在获得用户提供的 `FIRECRAWL_API_KEY` 或确认采用本地自托管后启用。优先用于站点 URL 发现、批量搜索、网页正文结构化和难抓站点的后备提取，不作为政府原始数据的真实性证明。

Firecrawl 返回结果必须回链到政府原始页面；搜索摘要、AI 提取结果和聚合答案不能直接写入真实支付账本。

### 7.4 学术研究工作流

采用 Codex 原生 `academic-research-suite` 进行论文检索、来源验证、引用核验和研究完整性检查。论文表格可用于二手数据复现，但必须记录论文、表号、单位、原始文本和是否属于理论测算。

## 8. 论文修改确认点

在以下任一条件出现时，Codex 必须暂停模型扩展，并询问用户是否允许依据实际数据修改论文：

1. 原稿宣称的 28 组省对无法由真实协议或支付支持；
2. 原稿使用双边 \(P_{ijt}\)，但实际只能识别省级或协议级金额；
3. 原稿把理论补偿、资金池、中央奖励或预测值表述为实际双边支付；
4. 数据只能支持描述性、案例或情景分析，不能支持因果或随机前沿解释；
5. 新数据导致样本期、研究对象、因变量定义或核心结论发生变化。

询问时应同时提供：

- 原稿当前表述；
- 新证据支持的观测层级；
- 保留原模型、降级模型和改写研究问题三种选择；
- 各选择对标题、摘要、方法、结果和结论的影响；
- 推荐的最小修改路径。

在用户确认前，不修改原始 DOCX，不把模拟结果写成经验事实。
